- **PostgreSQL port: a date or time literal written with a time zone goes to the source, and both bounds of a `BETWEEN` are checked** (#3024). PostgreSQL does not read a zone written in a `TIMESTAMP`, `DATE` or `TIME` literal (`TIMESTAMP '2026-03-02 10:00:00+02'` is 10:00, in any session time zone). Measured, the copy does the same with an offset, refuses a zone's name, and takes an offset PostgreSQL refuses (`+16`); the port now sends such a literal to the source instead of relying on that. The check of `BETWEEN` looked only at the lower bound: a string with a zone, or text compared by order, in the upper bound (`$1 BETWEEN $2 AND name`) reached the copy, which compares text by bytes where the source uses its collation. An operator that ends in `+` or `-` is cut as PostgreSQL cuts it, so `qty =-5` is `qty = -5` and stays on the copy.
- **PostgreSQL port: a row read as of a moment keeps the fraction of a second** (#3025). A timestamp that came from the snapshot was written without it (`03:04:05` for `03:04:05.12`). It is written as PostgreSQL writes it: up to six digits with the trailing zeros dropped, a year before 1 with `BC`, and `infinity` / `-infinity`.
- **PostgreSQL port: savepoint names are told apart as PostgreSQL tells them** (#3026). `SAVEPOINT "A"` and `SAVEPOINT a` were one savepoint to the port, so after both, `ROLLBACK TO "A"` brought back the session settings (`TimeZone`, `search_path` and the rest) of the wrong one and gave them to the source again. A name without quotes is folded to lower case (`A` to `Z` only), a name in quotes is kept as written, and both are cut to 63 bytes.
- **PostgreSQL port: the not-captured marker is never served as a value** (#3027). A row read as of a moment is not meant to hold the marker that stands for a column PostgreSQL never sent; if one ever did, the read is refused with an error that says so, as for the unchanged-TOAST marker, instead of returning the marker's JSON.
