- **The PostgreSQL port remembers a statement shape that needed the order written on the copy** (#3289). When a statement runs out of memory on the copy in the engine's join order and then answers when run again with its joins in the order written (#3288), the port remembers its shape for that server: the statement with every value as `?`, plus the schema and `search_path`. The next statements of that shape run in the order written from the start, so the CH-benCHmark's Q9 takes one run of about 6 s instead of a failed one of 22 to 34 s plus the retry. The answer is the same, only the plan changes. Only a retry that answered teaches the port anything. A remembered shape keeps the join check for the order written, and gets at most half of what is left of the client's `statement_timeout`. One that runs out of memory or time in the order written is forgotten and goes to the source as `copy_refused_after_written_order`, with no third run. Each shape is kept 24 hours from when it was learned, at most 4,096 per server, in memory only. `/status` counts `join_checks.written_order_remembered` and, as part of it, `written_order_forgotten`. The MySQL port is not changed.
