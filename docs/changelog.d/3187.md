- **PostgreSQL fresh mode: a table whose recent changes cannot be completed from its copy in time stops trying until its next snapshot** (#3187, part of #3076). On a large table that is not at `REPLICA IDENTITY FULL`, the read of the table's copy for the large values a change did not send can take longer than the 2 minutes a tail build gets. Each build used to fail, wait, and try again with no end, spending one to two CPUs while the table still had no recent changes. Now the second build over the same snapshot whose read runs out of time stops there. The log says so once, and the table answers from its snapshot, as it already did while the builds failed. At the table's next snapshot it is tried again. A build cancelled, or one whose time was already up before the read began, is not counted. MySQL and MariaDB sources are not touched.
