- **The PostgreSQL port in fresh mode sends to the source what the MySQL router sends to MySQL, except heavy statements** (#3291, closes #3116). On a connection with a forwarding user, a light statement whose tables' recent changes are not ready after fresh mode's wait, or whose recent changes are older than what an earlier answer of the copy on the same connection read, is no longer answered by the copy with only a notice: it is refused before the copy runs anything, and the source answers it (`copy_too_old` in `/status`). A heavy statement, one whose plan on the source is over the port's cost thresholds, stays on the copy in both cases and is answered with older data and the notice, as before. This holds over the simple and the extended protocol, and a connection keeps what it was shown until it closes. A connection with nowhere else to send the statement (a server that hides tables or columns) still gets the copy's answer with the notice, as a MySQL connection that does not route. A light statement the source cannot take right now (`source_unreachable`, `capture_gate`) stays on the copy with the notice. `/status` counts heavy statements answered with older data under `heavy_older_on_copy` (`tails_not_ready`, `older_than_earlier`), and the router logs both kinds of decision at info level once a minute. On the PostgreSQL port, a table that cannot have its recent changes laid over it, or a statement whose tables cannot be told from its text, is no longer read from the snapshot with nothing said: a light statement goes to the source, a heavy one gets a notice.
