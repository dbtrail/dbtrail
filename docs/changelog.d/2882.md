- **PostgreSQL: a server just added no longer takes a second full read around the turn of the hour** (#2882). A snapshot update reads the changes from one minute before the snapshot. When that window began in the hour before the index's first one (the snapshot was taken just before the index's tables were created, or in the first minute of that hour), the update refused with "query covers hours with no data (rotated and not archived)" for an hour that never held anything to rotate, and DBTrail read the whole source again instead. The update no longer counts the hours before the index's first one as missing when the index records that it never dropped anything and that capture started at or before the snapshot; the changes of those hours are in the index's first partition and are read as before. An index that cannot show both still refuses. MySQL and MariaDB are unchanged.
