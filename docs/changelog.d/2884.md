- **MySQL 9.7 LTS is a supported source and index, next to 8.0 and 8.4** (#2884). The MySQL integration suite now runs on 9.7 as a third cell in CI and before every release, with the server's GTIDs turned off as on the other two cells. Percona Server 9.7 is listed with it. The 9.x Innovation releases between LTS lines are not supported. On a 9.7 source the MySQL port used to send every statement to MySQL: 9.7 writes `EXPLAIN FORMAT=JSON` in a new layout by default, which the router does not read, so no statement could be routed to the copy and the reason given was `explain_failed`. The port now asks a MySQL 9 source for the 8.x layout on each connection it opens (`SET SESSION explain_json_format_version = 1`); a client's own `EXPLAIN FORMAT=JSON` through the port shows that layout too. See [the router's plan step](time-travel-sql.md).
- **`recover-cascade` on a source that writes its cascades to the binary log** (#2884). MySQL 9.6 and later (9.7 among the supported versions) log the child rows a foreign-key cascade deletes or rewrites, unless started with `innodb_native_foreign_keys = ON`. `recover-cascade` (the command, the web interface and the MCP tool) looked for children still pointing at the parent, found none (their last change was their own logged delete), and put back the parent alone. It now reverses the logged child changes of the parent's own transaction instead. Which case applies is read from the source and kept with the index: capture records each start of the source server and its `innodb_native_foreign_keys` (when it connects, then once a minute, and at every schema snapshot), and a parent change is judged by the start whose readings surround it, so an index that spans an upgrade from 8.4 is right on both sides. A change no readings surround is reconstructed as before and marked incomplete when the index holds child changes of its transaction. See [recover-cascade](query-and-recovery.md#recover-cascade-reverse-fk-on-delete--on-update-cascade--set-null).
- **The first copy of a MySQL 9.7 source works with the pinned mydumper**, which crashes there unless its sessions use `explain_format = TRADITIONAL` (9.7's default is `TREE`); DBTrail already passes that setting (#2211). The MySQL integration suite now makes a real first copy with mydumper on every MySQL version it runs.
