- **PostgreSQL port: a `char(n)` column read from the copy comes without its padding** (#3219). **Upgrading: this changes what a client sees.** PostgreSQL fills a `char(5)` with blanks and shows `'ab   '`; when the copy answers through the port it now shows `'ab'`. The same statement still shows the blanks when PostgreSQL answers it. A value stored with trailing blanks on purpose loses them on the port, and one made only of blanks is shown as an empty string, not NULL. Only what the port shows changes: the stored data, recovery, reconstruction, the SQL page, dashboards and downloaded view scripts keep the stored value. An array of `char(n)`, a `bpchar` with no length and a domain over `char(n)` are not trimmed. MySQL and MariaDB sources are not affected.
