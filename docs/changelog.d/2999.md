- **PostgreSQL: the readers that need the earlier row handle a table that is not at REPLICA IDENTITY FULL** (#2999). `recover` and `recover-cascade` refuse, before writing anything, a window holding an `UPDATE` or `DELETE` whose earlier row PostgreSQL sent only as its key, naming every table affected and the `ALTER TABLE ... REPLICA IDENTITY FULL` that makes later changes undoable; a window of `INSERT`s still undoes. `verify --check recover` counts such a change per table as not checkable (`changes_not_captured`), never as a mismatch. The Iceberg export accepts the key-only earlier row and carries an unchanged large value from the row's earlier change, or refuses the table with its own message. The MySQL port refuses the marker if it ever sees it. Nothing produces the marker yet: no behaviour change in this release, and none at all for MySQL.
