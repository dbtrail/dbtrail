- **The PostgreSQL port answers in fresh mode** (part of #2756). A PostgreSQL server in fresh mode, the default, now answers on the PostgreSQL port (5433) with the changes captured since its last snapshot laid over the copy, so a row written a moment ago shows without waiting for the next snapshot update. Fast mode answers from the snapshot alone. Each server's choice (its Snapshots page, or `bintrail-console port mode <server> fresh|fast`, which no longer refuses a PostgreSQL server) and `BINTRAIL_SQL_TAILS=on|off` (`SQL_FRESH` in the compose `.env`, now passed to the `pg-router` service too) decide as on the MySQL port. The recent changes take up to a fifth of the PostgreSQL router's memory for each server in fresh mode, on top of the statements', and `--workers` is not lowered for them. Not covered yet, where the answer comes from the snapshot with a NOTICE: a few seconds after each snapshot update and at a table's first statement, a join with a table that has had no write since capture started, tables under `BINTRAIL_PG_TABLE_DELTAS`, and the wait for the source (`BINTRAIL_SQL_FRESH_WAIT`). MySQL and MariaDB servers are unchanged.
