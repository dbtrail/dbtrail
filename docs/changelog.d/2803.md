- **The PostgreSQL port heads an unnamed column as PostgreSQL does** (#2803). A result column the statement gives no name was headed with the copy engine's text for it (`count_star()` for `count(*)`, `(id + 1)` for `id + 1`), so a client that reads columns by name (`row["count"]`, an ORM mapping an unaliased aggregate) did not find them. The port now names them by PostgreSQL's rule, read from the statement's parse: a function call takes the function's name (`count`, `sum`, `lower`), a cast of an expression takes the type's name (`int4`, `numeric`, `timestamptz`) and a cast of a column or a call keeps theirs, `CASE` is `case`, and an operator or a constant is `?column?`. A column with an alias and a bare column are not touched. The copy's own heading stays where the rule cannot be sure: a select list that holds a `*`, a cast of an expression to `text`, `varchar`, `char`, `real` or `float` (the engine holds each group as one type), a column written with upper-case letters inside a cast, and `VALUES` lists. It costs no second parse: the names are read from the parse the copy already makes of every statement. The MySQL port and the web interface's SQL card show the same headings as before.
