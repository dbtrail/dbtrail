### Changed

- PostgreSQL port: a `char(n)` column, which the copy holds without its trailing blanks, no longer sends every statement that names it to PostgreSQL. Where the padding cannot change PostgreSQL's answer (shown, grouped, counted, sorted, compared with a plain string with no trailing blank, `IN`, `LIKE 'x%'`, `IS NULL`, cut with `substr`) the copy answers; every other use stays with PostgreSQL. Sorting by such a column follows the copy's order of text, as for any text column. (#3276)
