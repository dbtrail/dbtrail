- **Fresh mode: a `WITH` block that reads another `WITH` block is answered with the tables' recent changes** (#3043). A statement such as `WITH x AS (SELECT * FROM orders), y AS (SELECT x.* FROM x) SELECT count(*) FROM y` was answered from the last snapshot alone, as old as that snapshot and with nothing saying so, on MySQL, MariaDB and PostgreSQL servers alike. The same happened with three levels of blocks, a recursive `WITH`, blocks inside a subquery, and a system table (`duckdb_views`) read beside a table. The inner block's name looked like a table the copy does not have, and a statement with such a name was read without any table's recent changes. It now reads them for the tables it names, and only for those: no other table of the copy is followed for it. On the PostgreSQL port with a forwarding user, these statements no longer go to the source with `copy_too_old` after the source answered the connection about the same table. Two cases stay as they were, by decision: a statement that reads a table through a table function, a file path or a qualified name the copy does not have as a view is answered from the snapshot, and so is a statement over a table that cannot have recent changes (capture does not record it, or its key is not supported); the answer's lag says how old it is.
