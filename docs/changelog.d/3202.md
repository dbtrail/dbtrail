- **PostgreSQL docs: what the port cannot see when capture stops saving its state** (#3202). The port takes a table's copy as current from the capture's record of dropped changes, saved with each checkpoint. `docs/postgres.md` now says that a capture which saved its state and then cannot save it again leaves later drops unrecorded, so the port can keep answering that table from its copy with no notice. Docs only; the fix is tracked in the issue. The same guide now says that a copy behind the source answers like a replica with lag, without telling the client, and that the lag limit `max_behind_source_seconds`, off by default as on the MySQL port, sends those statements to the source when there is a forwarding user.
