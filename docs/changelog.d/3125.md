- **PostgreSQL port: an answer read from the snapshot alone has an age, and a lag limit works in fast mode** (#3125). A statement that read a table without its newest captured changes (every table read in fast mode, a table with no recent changes in fresh mode) never had an age: `/status` counted it under `data_age_unknown`, and on a server with a lag limit (`max_behind_source_seconds`) every one of them went to the source, so a limit in fast mode left the copy answering nothing. The age is now read from what each snapshot file already records, the instant it holds every committed change before, and the statement is as old as the oldest of the tables it reads. `/status` reports it in `data_as_of`, `data_age_seconds` and `data_age_max_seconds`, `SHOW dbtrail.router_status` in `last_answer_indexed_through` and `last_answer_age_seconds`, and a lag limit sends a statement to the source only when that age is past it (`copy_behind_source`). The number errs old: it sits a minute before the file was written, it is never later than the file's last write on the router's machine, a table with no change keeps the instant of the update that last wrote its file, and a quiet source or a stopped capture make it grow. Three cases can still read younger than the data is, and `docs/postgres.md` names them: a source clock ahead of the router's on a file that took minutes to write, a schema removed and added back later, and a publication that does not publish `TRUNCATE`. There is no age, and the source answers under a limit, for a file that records no instant (a full read from before 0.137.0 that no update has written again, a copy outside a local folder), a table capture lost or dropped changes of, a table outside the schemas the server captures now, a capture with no saved state for more than a minute, and an index that cannot be asked. A statement that reads every table with its recent changes does no extra read of the index. The port's own listing of the copy's columns is no longer held to the limit: with the copy past its limit that listing was refused, and statements were counted as `veto` instead of `copy_behind_source` or `copy_age_unknown`. No snapshot format change; MySQL and MariaDB servers are not affected.
