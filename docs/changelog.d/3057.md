- **PostgreSQL port: a statement is read as PostgreSQL reads it before it is sent to the source, and what cannot be read is not sent** (#3057). The port sends its server's source only reads. What decided that a statement was a read were three readers of its text that did not agree with PostgreSQL, or with one another, on where a comment, a string or a dollar quote ends. One scanner now cuts the text the way PostgreSQL's does (a `--` comment ends at a line feed or a carriage return, block comments nest, an `E'...'` string and a dollar quote start only where PostgreSQL starts one, a string written in pieces a line apart is one string), and the forwarding screen, the session statements and the catalog detection are built on it. A text it cannot cut with certainty (a quote or a comment left open, a number with letters run into it) is refused with `0A000` and nothing of it is sent.
- **PostgreSQL port: `BEGIN`, `COMMIT`, `ROLLBACK` and `SET TRANSACTION` go to the source in the port's own words** (#3057). They were sent as the client wrote them. The port now writes them from the modes it read (`BEGIN READ ONLY`, with the isolation level named) and, behind its `BEGIN` in the same round trip, has the source say that the block is read-only; a block that is not is never used, and the statement answers `08006`. A `BEGIN` inside an open extended-protocol batch costs one more round trip; nothing is added per statement.
- **PostgreSQL port: refused although it begins as a read** (#3057). `SELECT ... INTO`, a `SELECT` that locks its rows (`FOR UPDATE`, `FOR SHARE`), an `INSERT`, `UPDATE`, `DELETE` or `MERGE` inside or after a `WITH` list, and `EXPLAIN` of anything but a query answer `25006` from the port; PostgreSQL refused them in the read-only transaction, with its own message. In a `WITH`, an `EXPLAIN` or a `DECLARE`, a column or alias named `insert`, `update`, `delete` or `merge` has to be written in double quotes.
- **PostgreSQL port: functions that act beyond a read are refused by family** (#3057), schema-qualified or quoted alike: stopping or cancelling a session, the server's files, large objects, WAL, backups, replication slots and origins, `pg_logical_emit_message`, `pg_reload_conf`, the statistics resets, `nextval` and `setval`, `txid_current` and `pg_current_xact_id`, the functions that rewrite an index (`brin_summarize_*`, `gin_clean_pending_list`), `ts_rewrite`. A function whose name holds letters past ASCII is sent only with its name in double quotes. `query_to_xml` and `ts_stat` are sent only when the statement they run is a plain string written in the statement and is itself a read. Measured on PostgreSQL 16 as an ordinary role: most of these are refused there by the read-only transaction or by the role's rights; `pg_logical_emit_message`, `txid_current` and cancelling the role's own sessions are not, and were sent before.
- **A stored forwarding URL for a PostgreSQL server that asks for a replication connection is not used** (#3057), as setting one already refused; `replication=` with no value counts.
- **CI: the PostgreSQL router's integration tests all run** (#3057). The console step that needs MySQL and PostgreSQL together selected `TestIntegrationPGRouter` by its exact name, so the router's other tests, the forwarding ones among them, skipped in every job. They are selected by prefix, with a tripwire for the forwarding tests.
