- **PostgreSQL capture no longer indexes the last saved transaction a second time each time it restarts** (#3196). A capture resumes from the position it saved, which is where the commit of the last transaction whose position it saved starts, and PostgreSQL sends that transaction again from there. Its rows went into the index a second time, so after every restart of the capture, clean or not, history, counts, archives and exports showed that transaction twice. The capture now recognizes that transaction when it arrives again and does not index its rows, or record its TRUNCATE, a second time. What is saved does not change, so an index written by an earlier version resumes the same way. Rows that an earlier version already indexed twice stay in the index: nothing removes them. MySQL and MariaDB sources are not affected.
