- **SQL on the copy of a PostgreSQL source reads an array as a list** (#2787). An array column was the text PostgreSQL writes for it, so `labels[1]` answered `{`, the first character, with no error, and `'red' = ANY(labels)` was refused. The views now read an array of whole numbers, `numeric(p,s)`, `real`, `double precision`, `boolean`, `date`, `timestamp`, `timestamptz`, `uuid` or text as a list of that type: an element by its position counted from 1, `ANY`, `unnest` and the length answer as on the source, a missing element stays missing, and an element holding a comma, a quote, a brace or the word NULL is read as written. An array of more than one dimension, or one whose first element is not numbered 1, fails the statement that reads it. Arrays of `bytea`, of `numeric` with no precision, of `json` and of the other types still read as text, stay text. See [how each type reads](postgres.md#how-each-type-reads-in-sql-on-the-copy).
