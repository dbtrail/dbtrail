- **PostgreSQL port: the `ORDER BY` of a report by a text column is answered by the copy, which sorts by bytes** (#3219). **Upgrading: this changes what a client sees.** A statement whose main `ORDER BY` sorted text went to the source, because PostgreSQL sorts text by the database's collation and the copy by bytes. The copy now answers it: the same rows, possibly in another order (`B, a, c` where PostgreSQL writes `a, B, c`, and accented letters after `z`), and **with a `LIMIT` or an `OFFSET` the rows kept can be other rows**. To have PostgreSQL's order, write `COLLATE "default"` on the key (`ORDER BY name COLLATE "default"`): the statement goes to the source. Still answered by the source, because there the order decides a value or which rows are counted: a window (`rank() OVER (ORDER BY name)`), `string_agg(x ORDER BY y)`, `min` and `max` of text, `name < 'b'`, `DISTINCT ON`, an `ORDER BY` inside a subquery or a `WITH`, a `char(n)` column sorted, and, in a statement that reads a column the copy holds as text and PostgreSQL does not (an enum, a domain, `money`, `inet`, `json`, a `numeric` wider than 38 digits), any key other than a real text column written by its name. A server without a forwarding user is not affected. MySQL and MariaDB sources are not affected.
