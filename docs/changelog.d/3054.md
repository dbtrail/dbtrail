- **Web interface: a PostgreSQL server's form asks whether the port may forward as the source user** (#3054). A PostgreSQL needed a second role, typed into the form, before its port sent anything to the source; the yes or no that `server add` asks on a terminal could not be given in the web interface. The form of a PostgreSQL server now has one box, unticked: "Let the PostgreSQL port send to this PostgreSQL, read-only and as the source user above, a SELECT the copy does not answer". Ticked, the port sends such a statement only when every table it reads is a table of the copy, as the terminal's yes does; it is saved through the same request (`PUT /api/servers/{id}/route` with `capture_account` alone), when adding a server or editing one, and only when the box was changed. The forwarding user of its own is folded behind "Advanced: use a separate forwarding user", and is in sight whenever the server has one saved. Nothing changes for a server that exists: the box shows what is saved, which is no unless somebody said yes. When an edit points the source at another user or address, the yes is taken back and the form says so. A session that may not change servers sees the box and cannot change it. The SQL clients page says, for the server picked in the sidebar, what the port sends to its PostgreSQL. A MySQL or MariaDB server's form is as before: no box, its two forwarding fields, and nothing about the capture account in what it sends.
