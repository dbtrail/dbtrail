- **The PostgreSQL router runs below capture's CPU priority, as the MySQL router does** (#3095, part of #3089). The `pg-router` service of the compose file now has `cpu_shares: 256` (`PG_ROUTER_CPU_SHARES` in `.env`), and its packaged systemd unit `CPUWeight=25`: the values the MySQL router has had since #2531. While the machine has idle cores nothing changes. When statements on the PostgreSQL port, capture and the snapshot update want the same cores, the kernel serves capture and the update first and the statements take longer. The PostgreSQL router does not read its priority: how many statements run at once and their threads stay `PG_ROUTER_WORKERS` and `PG_ROUTER_THREADS`. **Upgrading:** the compose file's version is unchanged. A file from before this change keeps the service at the default priority, as it ran until now; take the current `docker-compose.yml` to get the lower one. A new install gets it; the installer run again over an existing install keeps the file that is there. `PG_ROUTER_CPU_SHARES=1024` in `.env` keeps the default priority with the new file. With the packages, the upgrade replaces the unit and restarts the service when it is running, so the priority applies with it (a stopped one gets it when it next starts); a unit changed with `systemctl edit bintrail-pg-router` keeps what it sets.
