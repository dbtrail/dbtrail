- **Engine Routing: arithmetic on an `UNSIGNED` whole number is answered by MySQL** (#2848). MySQL computes `+`, `-`, `*` and `%` with an `UNSIGNED` operand as a `BIGINT UNSIGNED` and refuses a negative result with error 1690. The copy holds `TINYINT` to `INT UNSIGNED` as signed numbers, so a routed statement got another type (`b - u` over a `BIGINT` and a `BIGINT UNSIGNED` was a `DECIMAL`) and, for a negative result, a number where MySQL refuses: `ui - 4` over an `INT UNSIGNED` holding 3 was `-1`, and `-u` over a `BIGINT UNSIGNED` holding 3 was `18446744073709551613` where MySQL answers `-3`. Under routing, a statement that does arithmetic on an `UNSIGNED` column of the tables it reads (known from the snapshot's table definition), or on `ROW_NUMBER`, `RANK`, `DENSE_RANK` or `NTILE` (a `BIGINT UNSIGNED` on MySQL: `ROW_NUMBER() OVER (...) - 10` is refused there and was `-9` on the copy), now goes to MySQL. Comparisons such as `u > -1`, `SUM(ui) - 1` and arithmetic on an `UNSIGNED` `DECIMAL` or `DOUBLE` stay on the copy, measured equal. So does a prepared statement with an argument bound as an unsigned integer in arithmetic (`k - ?` with a `uint64` 10 was `-7` on the copy and error 1690 on MySQL). The port without routing still answers from the copy.
