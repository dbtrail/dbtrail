- **The snapshot schedule asks a PostgreSQL source whether capture is caught up** (#2844). When nothing was indexed since an old snapshot, the schedule asks the source before it decides; for a PostgreSQL server it did not, and skipped the slot with "PostgreSQL sources are not compared yet" whatever the capture's own record said. It now reads that record and compares the capture's saved position with how far the source's WAL is flushed. Two positions that are equal confirm the capture is caught up. A loss on record since the snapshot takes a full read, which is the only way to read those changes again; before, such a server was skipped indefinitely. Nothing else does: a source that is ahead (its WAL moves for the whole PostgreSQL server), a capture that stopped saving, or a capture past its source skip the slot with the reason on the Snapshots page, and the last two are warnings in the log.
