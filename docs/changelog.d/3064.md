- **`server add` asks a PostgreSQL once whether the port may forward with the user DBTrail connects with** (#3064). In place of the question for a forwarding user of its own: may the PostgreSQL port send to your PostgreSQL, read-only, a `SELECT` whose every table is a table of the copy, as that user, when the copy does not answer it? Enter is yes. Without a terminal, the Docker `dbtrail` command among them, nothing is asked and the answer is no, and the command says so, unless `--capture-account` or `capture-account = yes` under `[dbtrail-forward]` says yes (`--no-capture-account` and `capture-account = no` say no). Not asked when `--forward-user` or `[dbtrail-forward]` names a forwarding user, which is set as before, nor with `--no-forward`. What was typed while the add ran is discarded before the question, so an early Enter is not a yes. A MySQL or MariaDB add is unchanged, and refuses the new options.
- **docs: the PostgreSQL port's connections with the capture role count toward that role's `CONNECTION LIMIT`** (#3064), at most `--max-source-connections` (16) at once; a role limit with no room for them can leave capture unable to log in again.
