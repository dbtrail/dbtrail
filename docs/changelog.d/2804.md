- **`bintrail-console pg-router`: the results held for clients that read slowly are bounded in all** (#2804). The PostgreSQL port builds a result whole and keeps it in memory until its client has read it. Each statement was bounded on its own, but the sum was not: many clients that read slowly held many results at once, with nothing refusing the next one. The port now counts the results it is sending, the copy's and time travel's alike, and holds at most 256 MB of them at once (the size the MySQL port has, with the same meaning; there is no flag for it on either port). A statement that arrives while that much is held is refused before it runs, with error `53000` and a sentence saying to run it again in a moment; it is never answered short. What a connection counted is given back when its answer has been written, when the statement fails, and when the connection ends. A client that asks for a result and then reads nothing of it for 60 seconds is disconnected, so it cannot keep its part for as long as it stays connected; a client that reads slowly is not. The MySQL port and `bintrail-pg flashback` are unchanged. See [SQL on the copy from `psql`](postgres.md#sql-on-the-copy-from-psql).
