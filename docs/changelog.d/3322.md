- **A PostgreSQL snapshot stores whole numbers, oid, date, uuid and numeric columns as their type** (#3315, #3322). Until now every column of a PostgreSQL source's snapshot file was text, and every read of the copy turned each value back into its type. A snapshot now stores `smallint`, `integer`, `bigint`, `oid`, `date` and `uuid` columns, and `numeric(p,s)` up to 38 digits with a scale below its precision, as the value itself. The views read them with the same types and the same values as before, so no answer changes; the files are smaller and reports read faster. The primary key's columns, every column of a table without a primary key, and every column of a table holding a value that would not read back as the same text (a `date` before the common era, a `numeric` `NaN`) stay text. Recovery, reconstruct, refreshes and views that follow later snapshots read a stored column as the exact text it was written from, and snapshots written before this read as they did. `BINTRAIL_PG_TYPED_COPY=0` stores every column as text.
