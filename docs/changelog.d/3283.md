- **MySQL and MariaDB fresh mode: tables keyed by a UUID, a date or a decimal get their recent changes** (#3283, #3159). Before, fresh mode laid recent changes only over a table whose primary key was made of integers. Any other table was read from its last snapshot, and so was any statement that joined it with other tables. A key can now also be `DECIMAL`, `DATE`, `DATETIME`, `TIMESTAMP`, `BINARY` (a UUID stored as `BINARY(16)`, for example) or `VARBINARY`, alone or combined with integers.

  A text key still has none, whatever its collation, `_bin` included: the copy compares text without MySQL's collation, so a key could match another row.

  A few key values turn off the table's recent changes until a snapshot newer than the change, and the table is read from its snapshot as before:
  - a `BINARY(n)` value that ends in 0x00 bytes (about 1 random UUID in 256);
  - a binary value whose text starts with `0x`;
  - a zero date;
  - a `DECIMAL` minus zero.

  An empty binary value written into the copy by a snapshot update is now stored as empty. Before, it was stored as the two characters `0x`.
