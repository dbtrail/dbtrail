- **Engine Routing: a division and an `AVG` are answered by MySQL, and a `SUM` of whole numbers is typed `DECIMAL` on the copy** (#2806). MySQL's `/` over whole numbers or a `DECIMAL`, and its `AVG`, return a `DECIMAL` with `div_precision_increment` more digits (`k / 7` is `0.1429`); the copy divided as a `DOUBLE` (`0.14285714285714285`), so a routed statement could get another type and other digits, and `FLOOR(k / 7)` a `DOUBLE` where MySQL sends a `BIGINT`. Under routing, a statement with a `/` (except inside the argument of `FROM_UNIXTIME`, which #2493's rule already reads), an `AVG` or MariaDB's `MEDIAN` now goes to MySQL, and so does one that writes a whole number from 9223372036854775808 up (a `BIGINT UNSIGNED` on MySQL). A `SUM` of whole numbers had the right digits and was sent as text; the MySQL port now sends it as a `DECIMAL` with no fraction, as MySQL does, with or without routing, so `SUM(k)`, `SUM(k) + 1` and `SUM(DATEDIFF(...))` stay on the copy with MySQL's type. `FLOOR(UNIX_TIMESTAMP(ts) / 86400)` outside `FROM_UNIXTIME` now goes to MySQL too.
