- **MySQL and MariaDB capture saves its position soon after it writes to the index** (part of #2645). The position in `stream_state` used to move only at the checkpoint, every 10 seconds by default, though complete transactions reach the index within about a second (#2666). Now it is also saved right after capture writes complete transactions, when none waits unwritten, at most every 150 ms, so the saved position is a fraction of a second behind what capture read. A transaction with no row capture keeps (another table's, a DDL) moves it too. It never names a transaction whose rows are not in the index, and a crash between a write and that save is cleaned up on resume as before. On a source written all the time this adds up to about seven one-row writes a second to `stream_state`; a busy source keeps its full batches, with no extra `INSERT`. The save logs `checkpoint saved` at debug; the one at the checkpoint interval keeps logging it at info. PostgreSQL capture is unchanged.
