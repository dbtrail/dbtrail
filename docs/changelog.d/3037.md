- **A process killed while it rewrote a snapshot no longer leaves its working files in the temporary directory for good** (#3037, part of #2513). A snapshot update or a `bintrail reconstruct` that was killed (out of memory, `kill -9`) left its `bintrail-fold-*` and `bintrail-compact-*` directories under the system's temporary directory, each as large as the changes it had written, and nothing removed them: five of up to 1.7 GB after four deaths in one test. Each directory is now locked by the process that uses it, and the next DBTrail process to start on the machine (a daemon that keeps snapshots as it starts, any other process at its first fold) removes the ones whose lock is free. A directory another running process still uses is held by its lock and is not touched, on the same or another installation sharing the temporary directory. Directories left by earlier versions, which took no lock, are removed once nothing was written in them for 24 hours. Only the directories of the same host and user are removed. On a temporary directory whose filesystem has no `flock`, nothing is removed automatically: a warning says so, and that what a killed process leaves there has to be removed by hand, or `TMPDIR` pointed at a local disk. A directory that cannot be removed, or whose lock cannot be asked for, is logged as a warning and does not stop the start.
