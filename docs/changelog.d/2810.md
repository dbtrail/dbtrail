- **Engine Routing forwards under the collation and character set the client asked for** (#2810). Every statement the routing port forwarded to MySQL ran under `utf8mb4_0900_ai_ci`, whatever the client's handshake named, so a comparison the connection's collation decides could answer differently than on a direct connection (`'10:47' < '1045'` is false under go-sql-driver's default `utf8mb4_general_ci` and was true through the port), and a `latin1` client read UTF-8 bytes (`é` as `C3 A9` instead of `E9`). The port now gives the session the client's collation: nothing more when it is `utf8mb4_0900_ai_ci`, the port's own, and otherwise one question to the source and a `SET NAMES` when the connection opens. A `COM_CHANGE_USER` gives the session the collation it carries, and a `COM_RESET_CONNECTION` the server's global ones, as MySQL does. A read-only port does not give a session a character set its screen cannot read safely (`gbk`, `sjis`, `big5`), as it already refused a `SET NAMES` to one. The copy still answers only a session that compares as it does, so **a Go client on go-sql-driver's default collation is now answered by MySQL on every statement**: add `collation=utf8mb4_0900_ai_ci` to its DSN (`utf8mb4_unicode_ci` on MariaDB 10.11) for the copy to answer.
