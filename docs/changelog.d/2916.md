- **PostgreSQL: a changed table can be published as its previous file and a small delta, behind a switch that is off** (part of #2757). An update of a PostgreSQL snapshot writes a table that changed in full, whatever the size of the change. With `BINTRAIL_PG_TABLE_DELTAS=1` it publishes the previous file, linked, and two small files beside it (`<table>.000000.pgdead` and `<table>.000000.pgnew`) with every change since that file was written; the table is still written in full when the changed keys pass one in four of the file's rows, when the file is older than the index is sure to reach back, or when the delta cannot be written. Do not turn it on yet: SQL on the copy does not read the delta, so a changed table would answer there as of its file, and the delta is in no record of the files a snapshot holds. Reading one row at a past moment, the shim and `verify` are not affected, and MySQL and MariaDB are unchanged.
