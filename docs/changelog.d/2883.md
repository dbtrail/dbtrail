- **PostgreSQL: a snapshot update no longer rewrites the tables that did not change** (#2883, first part of #2757). Every update used to read and write every table again, changed or not, so on a large database the size alone set how often the copy could be updated. A table with no change is now carried forward as on MySQL: the new snapshot reuses the previous file (a hard link, so it takes no extra disk) and the table is not touched. The first update after a full read still writes every table once, and a table left unchanged for long is written again before the index drops the changes its file starts from. A table that did change is still written in full, and so is every table of a `bintrail baseline refresh` run from the command line, which cannot tell how long the index keeps its changes. The schedule now reads where a PostgreSQL snapshot's readers start from its files, so a snapshot holding carried tables is updated before it can no longer be rebuilt.
