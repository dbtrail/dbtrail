- **PostgreSQL port: a capture that stops saving its state while the source writes no longer leaves the copy answering as current** (#3202). Whether a table's copy is current is decided from capture's record of the changes it dropped, saved with its checkpoint. A capture that saved once and then could not save again kept its later drops in memory only, and the port kept answering such a table from its copy, with no notice. Now, when capture's last save is more than a minute old by the index's clock and your PostgreSQL's WAL is past the last position capture saved (read as the forwarding user, only once the save is that old), every statement that reads a table of that server's copy is answered by your PostgreSQL, heavy ones included, counted as `capture_state_stale`. A quiet source is not affected. Where a statement cannot go to the source (a server that hides tables, `source_unreachable`, `capture_gate`, `SUMMARIZE`) the copy answers it with a NOTICE, and so it does when the source cannot be asked where its WAL stands. `/status` shows `capture_state` with the reason and counts `capture_state_on_copy`; the router logs a `WARN` when it starts and an `INFO` when it ends. It ends by itself once capture saves again. A capture stopped by the operator is treated the same while the source writes. Not covered: a first run that has saved no position yet, and a row saved without a trusted sent-through position (`bintrail-pg reset`).
