- **PostgreSQL: `recover-cascade` refuses instead of returning a parent-only script** (#3004). PostgreSQL capture does not record foreign keys yet, so the cascade's children could not be found and the script brought back the parent alone while calling itself complete. The command line, the console and the MCP tool now refuse up front and explain the undo that works: the children are captured as their own deletes in the parent's transaction, and `bintrail-pg recover --schema <schema> --gtid <commit position> --suppress-triggers` undoes that whole transaction (trigger suppression lets PostgreSQL accept the children before the parent; it needs superuser, or `GRANT SET ON PARAMETER session_replication_role` on PostgreSQL 15 and later). MySQL and MariaDB are unchanged.
