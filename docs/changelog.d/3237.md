- **PostgreSQL port: three statements that sort text were answered by the copy in another order** (#3237). PostgreSQL sorts text by the database's collation, the copy by bytes, so a statement that sorts text goes to the source. The port finds the text by what the statement names, and three statements that sort a text column read as having none: a position behind a star (`SELECT * FROM t ORDER BY 2`, the second column being text), a name the statement gives a value that is also a column's name (`SELECT name AS name FROM t ORDER BY name`), and a text column named like a word of `ORDER BY` (`ORDER BY last`, `ORDER BY first DESC`). The client got the right rows in the copy's order, with no error. All three now go to the source. What stays on the copy: `SELECT * FROM t ORDER BY 1` over a number or a date, a star over rows that hold no text, `sum(qty) AS qty ... ORDER BY qty`, and `amount AS amount` over a numeric. Also fixed, the other way round: on a copy with a text column named `last` or `first` in any table, every `ORDER BY ... NULLS LAST` was sent to the source; it stays on the copy.
