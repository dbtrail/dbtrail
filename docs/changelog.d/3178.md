- **PostgreSQL capture can start on a source that always has an older write transaction open** (#3178). PostgreSQL finishes creating a replication slot only when the write transactions open at that moment have ended, and capture gave that 30 seconds. On a source with a long batch or a session left in a transaction, the creation was cut and retried without end, so the source was never captured unless a snapshot made the slot first. Capture now waits for as long as it takes, like a snapshot's own creation of the slot. While it waits, the server shows CREATING SLOT and names the oldest write transaction open: its session and how long it has been open, plus its user and database when it belongs to the captured database. A prepared transaction is shown as such, without its name, and the statement is never shown, and the log repeats it once a minute. Stop ends the wait and leaves no slot behind. The server no longer reads as running before replication has started. A snapshot asked for during this wait still waits up to 5 minutes for the slot and is then refused with nothing read. MySQL and MariaDB sources are not affected.
