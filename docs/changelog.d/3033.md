- **`server add` takes a PostgreSQL's forwarding user, as it does a MySQL's** (#3020). `server add --flavor postgres` refused `--forward-user` and `--no-forward` and never asked, so every PostgreSQL server started with the copy answering alone, and a statement the copy could not answer got an error instead of going to the source. It now asks for the forwarding user once the server is added, on a terminal (Enter skips it), or takes it from `--forward-user` or from `[dbtrail-forward]` in the option file; `--no-forward` does not ask. It is saved the way `server forward-user` saves it, with the same refusals (the role DBTrail captures with, a source it cannot be laid over), and a refused role leaves the server added and recording, says why and exits 1. Without one, the command now says so and prints the line that sets it. `server forward-user` still sets, changes and removes it later. No login is tried with the role at add: the PostgreSQL port logs in with it the first time a client needs the source.
