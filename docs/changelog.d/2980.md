- **PostgreSQL: a capture that starts again no longer indexes changes twice** (#2775). Capture makes rows durable and then saves its position. When it stopped between the two (a crash, a kill, a failed save), or while a very large transaction was being indexed in parts, the rows past the saved position stayed in the index and PostgreSQL sent them again on the next start: every one of them was then in the index twice, for queries, recovery and snapshots, for good. A start now removes what the index holds past the position it resumes from, as the MySQL capture has done since #759.
