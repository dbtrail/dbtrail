- **The PostgreSQL port no longer answers from the copy a table changed on the source since its snapshot** (#3293, closes #3251). PostgreSQL does not announce an `ALTER TABLE` to capture, so after a change no write followed (a column retyped, its modifier changed, added, dropped or renamed, the table dropped and created again) the copy answered with the snapshot's columns, and rows PostgreSQL would not return, with no notice, until the table's next snapshot. Before the copy answers a statement, the port now reads from the source's catalog, as the forwarding user and never a row of a table, the OID and columns of the tables the statement reads, kept one second per table, on one of the port's connections to its sources. A difference sends the statement to the source (`copy_shape_differs` in `/status`), heavy statements included; on a server that hides tables or columns it is refused with `55000`, and the client is told the table changed, never which columns. When the source cannot be asked (down, slower than two seconds, no connection to it free), the copy answers as before, with a NOTICE that the tables could not be checked (`copy_shape_unchecked`). Not covered: a rewrite that keeps every column's type (`ALTER COLUMN n TYPE int USING n + 1` on an `int` column) changes values and no column, and still shows the old values until the table's next full read.
