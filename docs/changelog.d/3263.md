- **A table read again alone on a source that writes nothing after the read is published** (#2640). The update waited for capture to pass the point of that read, judged by the changes it had indexed, so with no write after the read it waited its five minutes and the slot took the full read after them: one more lock and one more read of the table than before this read existed. Capture's saved position now counts: when capture follows the source by binlog position and has saved a position past the read, and nothing it indexed is stamped after the update's target time, the update ends every table at that position. With capture by GTID, whose saved position can fall inside a transaction, after a binary log rotated since the last transaction, and in another numbering of the binary log, the wait is as before. Every table's window then reaches that position, so another table truncated between the last indexed change and the read is refused, as it would be on a source that kept writing.
