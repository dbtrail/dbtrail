- **The PostgreSQL port announces each column's PostgreSQL type, and sends binary results** (#2768). `bintrail-console pg-router` used to announce every result column as `text`, so `pgx` returned a `string` where the source gives an `int64` or a `time.Time`, psycopg a `str`, and JDBC's `getObject` a `String`. A column of the table now carries the type, type modifier and size the source announces (`integer`, `bigint`, `smallint`, `numeric(p,s)`, `real`, `double precision`, `boolean`, `date`, `timestamp`, `timestamptz`, `time`, `timetz`, `uuid`, `bytea`, `text` and one-dimensional arrays of those), and a client that asks for results in binary gets them in binary. Checked against PostgreSQL 16, column by column: the same description and the same bytes in text and in binary, and the same values of the same types through `pgx` (every mode), psycopg 3 (text and binary cursors) and JDBC (`getObject` and `getString`). Announced as `text`, with PostgreSQL's text: `json`, `jsonb`, `varchar(n)`, enums and the other columns the copy keeps as text, `interval` (JDBC asks the server's catalog how to read one, which the port does not answer), a type of the copy's engine PostgreSQL has no equivalent for, time travel and `SHOW`. An expression keeps the type the copy computes it with (`avg()` of integers is `double precision` here). A cell with no binary form for its type is refused with `0A000` when a client asks for binary, never sent as other bytes, and a result in binary is counted in the port's result budget at its binary size. A prepared statement's unnamed column is now headed as PostgreSQL heads it on the extended protocol too (`count`, not `count_star()`).
