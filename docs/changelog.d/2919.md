- **Fresh mode no longer rebuilds every table's recent changes at every snapshot update** (#2919). A snapshot update writes into a folder of its own and links each table's file into it, so the file keeps its contents and changes its name. The trim that moves a table's tail to a newer snapshot (#2485) asked for the same name, so it never ran: every update rebuilt every tail from the index while statements waited. Measured at 400 transfers a second on a 10-million-row table: every copy answer stalled together for 1 to 2.3 s after each update at 50 clients, and at 200 clients, or on the first statement after an update nobody read, heavy reads ran out of the 3-second wait and went to the source MySQL (`copy_too_old`), each a full scan there. The tail is now trimmed in memory when the new snapshot holds the same file (same device, inode, size and modification time), with no read of the index. A file written again (a full backup, a compaction, snapshot folders on two filesystems) is still rebuilt. A finished build also wakes the tails' update at once, so a statement waiting for it does not wait out the one-second pause. The first statement over a table in a router's life still builds its tail from the index.
