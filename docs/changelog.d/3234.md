- **In fresh mode, a statement over tables that already have recent changes to read no longer waits for an update of them** (#3234). Every statement on the MySQL and PostgreSQL ports waited for any update of the copy's recent changes that was running, however long it took. It now goes on at once and reads the last version published, so during an update an answer can be behind by up to that update's length, with no notice; with an update held for 4 s, a report went from 4 s to under 65 ms. With `BINTRAIL_SQL_FRESH_WAIT` on, a statement on a MySQL source waits for the running update first, so a client still reads its own write. A table with no version yet still waits for the running update, for at most half of the statement's time limit, and then goes the normal way: your database answers it, or the copy does and says it read the snapshot alone.
