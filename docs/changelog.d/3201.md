- **The PostgreSQL port decides before running, and a cheap read no longer pays for a new connection** (#3201, closes #3086, #3046, #3045).
  - A statement whose tables' recent changes are not ready, on a connection the source already answered about them, no longer runs on the copy only to have its answer thrown away: it goes to the source at once (`copy_too_old`). Where nothing else can answer, the snapshot answers with its warning, as before.
  - A client's connection to the source is kept between its statements, as the MySQL port keeps its own, and reset (`DISCARD ALL`) before it is used again, so nothing one statement leaves in the session reaches the next. It is never held from other clients: when every connection the port may open (`--max-source-connections`) is taken, the one idle longest is ended for the client that waits. A timer ends it 60 seconds after a statement last used it, whether or not the client comes back. A lookup by key went from 6.8 ms to 1.1 ms through the port.
  - A statement whose plan cost sits near the routing threshold no longer changes side on its own. Per server and across connections, a statement shape keeps the side that last answered it by its plan while the plan stays within 10 % of the threshold (to the copy from 55,000, back to the source under 45,000; the scan rule's 1,000,000 rows likewise). The plan is still asked for every statement, and a change of side is logged.
