- **Messages and docs no longer send you to a "Working folder" row the web interface does not have** (#3066). The Snapshots page has saved only "Delete by age" since 0.89.0, but the refusal and the failure card of a full read with too little disk, the startup log, `bintrail doctor --staging-dir`, `docs/console.md`, `docs/capacity.md` and `docs/ecs.md` still said to change the working folder in the web interface's backup settings. They now name the two places that set it, `BINTRAIL_CONSOLE_BASELINE_STAGING` or `console-baseline-staging` in `dbtrail.cnf`, followed by a restart. The docs also said the backup settings name the folder in use when none is set; the startup log does.
- **A working folder, lock mode or table list saved by 0.85 to 0.88 still comes first, and the docs and `dbtrail config check` say how to remove it** (#3066). Those versions could save the three from the web interface, and a value saved then is still in the servers file and wins over the variable and the option file. The option reference and the comments of `dbtrail.cnf` say so, and `dbtrail config check` used to answer "Change it there" for such a line, which is no longer possible: it now names the request that removes the saved value, `PUT /api/backup-settings/daemon/staging_dir` (or `lock_mode`, `verify_tables`) with `{"use_startup":true}`. Nothing changes in what DBTrail does.
