- **An update of a PostgreSQL snapshot warns for a table that entered capture after the snapshot was taken** (#2862). Since #2843 a capture that started at or before the snapshot proves there is no gap, for every table. That proof is about the capture, not the table: a table added to the publication later was covered by it too, and its changes from before the add are in neither the snapshot nor the index. Capture already records the first time it sees a table that the publication did not hold when it started (a schema-change row, since #2441). A fold now reads that row, and when it is placed after the snapshot's floor it warns "possible gap between baseline and this table's first indexed event", saying that the table entered capture after the snapshot. A table that has no such row is treated as before. Not detected, because the index holds no record of it: a table let in by a wider `--schemas` or `--tables` at a restart, a table added to the publication while capture was stopped or before a restart that came ahead of its first change, and an index written before these rows were. A table that entered capture before the snapshot and had no change until after it gets the warning too, until the next snapshot: its record is placed at its first change. MySQL and MariaDB record nothing about a table entering capture, so their check is unchanged.
