- **SQL on the copy no longer shows the engine's settings, secrets or variables, and its errors no longer name folders of the host** (#3096). The engine's catalog functions are allowed by name instead of by prefix: `duckdb_tables`, `duckdb_columns`, `duckdb_schemas`, `duckdb_views`, `duckdb_databases`, `duckdb_types`, `duckdb_functions`, `duckdb_keywords`, `duckdb_constraints`, `duckdb_indexes`, `duckdb_sequences`, `duckdb_dependencies` and `duckdb_coordinate_systems` still answer; every other engine table function is refused with the copy's usual "is not allowed here" error, including one a future engine version adds. Refused on every server: the engine's settings (`duckdb_settings`, `pg_settings`), session variables (`duckdb_variables`, `getvariable`, `SHOW VARIABLES`), secrets, extensions, file cache, temporary files and logs (`duckdb_logs`, with or without parentheses); `current_setting` still answers for the settings that hold no path (time zone, threads, memory) and is refused for those that hold a path, a list of folders, a repository or a proxy. On a server with hidden rules `pg_get_viewdef` is refused too. An error sent to a client shows `<hidden>` where it named a folder of the copy, the statement's temporary folders, or the engine's folder under the service user's home; the original text is in the log. Applies to the MySQL port, the PostgreSQL port, the console's SQL panel and the MCP SQL tool. Not changed, on purpose: on a server without hidden rules the views' text and the file readers still name the copy's own files, as the views file the console offers does. A statement that called one of the refused functions now gets an error; reads of the copy's tables, `SHOW TABLES`, `DESCRIBE`, `information_schema` and the rest of `pg_catalog` are unchanged.
