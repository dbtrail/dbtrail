- **SQL on the copy no longer shows the engine's settings, secrets or host folders** (#3096). The engine's catalog functions are allowed by name instead of by prefix: `duckdb_tables`, `duckdb_columns`, `duckdb_schemas`, `duckdb_views`, `duckdb_databases`, `duckdb_types`, `duckdb_functions`, `duckdb_keywords`, `duckdb_constraints`, `duckdb_indexes`, `duckdb_sequences`, `duckdb_dependencies` and `duckdb_coordinate_systems` still answer; every other engine table function is refused with the copy's usual "is not allowed here" error, including one a future engine version adds. Refused on every server: the engine's settings (`duckdb_settings`, `pg_settings`, `current_setting`), session variables (`duckdb_variables`, `getvariable`), secrets, extensions, file cache, temporary files and logs; on a server with hidden rules, `pg_get_viewdef` too. Errors sent to a client replace the folders of the copy, of the statement's temporary files and of the engine under the service user's home with `<hidden>`. Applies to the MySQL port, the PostgreSQL port, the console's SQL panel and the MCP SQL tool. A statement that called one of these functions now gets an error; reads of the copy's tables, `SHOW`, `DESCRIBE`, `information_schema` and the rest of `pg_catalog` are unchanged.
