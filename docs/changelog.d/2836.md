- **Engine Routing: the copy answers a statement the connection's collation cannot change, under any collation** (#2836). Since #2810 a client's session is under the collation it asked for, and the copy answered only one that compares as it does, so a Go or PyMySQL client on its driver's default `utf8mb4_general_ci` (directly, or behind ProxySQL, which passes it on) got every answer from MySQL. Now, under any connection collation with results in `utf8mb4`, the copy answers a statement with no string literal, no double-quoted string, hex or bit number or placeholder, and no call other than `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, the number and date functions and the keywords that open a list: text there is only columns, which carry their own collation (measured on MySQL 8.0.46: `ORDER BY`, `GROUP BY`, `DISTINCT`, `MIN`/`MAX`, comparisons, `LIKE`, `IN` and `CASE` over columns answer the same under `utf8mb4_general_ci` and `utf8mb4_0900_ai_ci`). A statement with a literal or a function that returns text (`CONCAT`, `DATE_FORMAT`, `LOWER`, `CAST`) stays on MySQL under such a collation. See [the session the copy answers under](time-travel-sql.md).
