- **A PostgreSQL snapshot update follows a row whose primary key changed** (#2760). An `UPDATE` that changed the primary key made the update refuse the table, and the schedule then read the whole table from the source again. It is now applied as a delete of the old key and an insert of the new one, as on MySQL and MariaDB, ordered against the other changes of both keys by commit LSN. It still refuses, with the reason in the message, when the change cannot be proven whole: no commit LSN in the index, an old row captured without every column, a key column missing from either row, or a stored key the old row does not spell. The last change of a PostgreSQL row is now chosen by commit LSN too, where it was the order the changes were read in; the two differ only when two commits carry times in the other order than their LSNs. MySQL and MariaDB are not changed.
