- **The PostgreSQL port takes prepared statements and parameters** (#2767). `bintrail-console pg-router` (and `bintrail-pg flashback`, which shares the wire) now speaks the extended query protocol, so JDBC, `pgx` in its default mode and psycopg 3 connect as they are, where they got one `0A000` error: named and unnamed statements and portals, `$n` arguments in text or binary format for the common types, the columns described before a statement runs, `Execute` with a row limit (a driver's fetch size), and PostgreSQL's error rule (after an error everything up to `Sync` is discarded). Each argument is written into the statement as a value, so the statement runs exactly as the simple protocol would run it with that value, and what the simple protocol refuses is refused with the same code. `BEGIN`, `COMMIT` and `ROLLBACK` now move the transaction status a client sees, on both protocols, and after an error inside a block every statement is refused (`25P02`) until `ROLLBACK`, as on PostgreSQL; a client that sent `BEGIN` and then a failing statement on the simple protocol used to go on unhindered. The port declares a parameter's type unknown rather than working it out: `$1 + 1` needs `$1::int + 1`. Checked against PostgreSQL 16 with `pgx` (every mode), psycopg 3 (text, binary, prepared) and JDBC (typed setters, `setFetchSize`). See [SQL on the copy from `psql`](postgres.md#sql-on-the-copy-from-psql).
