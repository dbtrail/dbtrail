- **PostgreSQL port: a WITH's column list is read as PostgreSQL reads it** (#3262). `WITH revenue0 (supplier_no, total_revenue) AS (...)` was taken for a call of a function, so every statement with a WITH column list went to the source, CH-benCHmark's Q15 among them. The copy now answers it, reading each name as the item at its position in the WITH's select list. A list over a `*`, one that names a name twice or a column of a table, and one over a `char(n)`, another column the copy does not hold as PostgreSQL does, or a column that is not a number still go to the source.
- **PostgreSQL port: a name given inside a table in FROM or a WITH is read by the copy in the WHERE around it** (#3262). The port sent to the source every statement whose WHERE named an alias of any select list, so CH-benCHmark's Q2, which filters on `m_i_id` and `m_s_quantity` of its table `m`, ran on the source. Now only a name read by the same statement that gives it, by a subquery of it or by a statement beside it goes to the source, where PostgreSQL refuses it. A name given to a `char(n)`, to another column the copy does not hold as PostgreSQL does, or to any column that is not a number (a date, a timestamp, text) still goes to the source wherever it is read, and so does a name a table of the same statement also has as a column. `WHERE id IN (SELECT ...) AND q > 2` is now checked after the subquery too.
