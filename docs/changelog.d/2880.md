- **PostgreSQL: a table whose primary key is `DEFERRABLE` is refused before it is captured** (#2880). A deferrable primary key is checked at the end of the statement or the transaction, so inside one transaction two rows can hold the same key, and a snapshot, which is kept by key, can then keep the wrong row or none. The snapshot update refuses the sequences it can recognise (#2760, #2875), and two it cannot: rows that are equal in every column share a key with nothing to tell them apart. The catalog says whether a key is deferrable, so `bintrail-pg doctor`, the web interface's checks when a server is added, and the capture when it starts now refuse a captured table with one, naming the table and the constraint and saying what to do: make the key not deferrable, or take the table out of the publication. A key made deferrable while capture is running is seen at the next start; until then the snapshot update's own refusals apply.
