- **PostgreSQL port: an application login that names another server as its database is refused** (#3087). **Upgrading: this can refuse a client that connects today.** A connection opened with a server's application login used to be connected to that login's server whatever database it named. Someone who wrote `dbname=staging` with the login of `prod` read `prod`, and nothing on the connection said so. Now, when the database named is another server of this DBTrail (its id or its name), the connection is refused with `28000` and an error that names the server the login belongs to: `user "app" is the application login of server "prod" and opens that server only, and database "staging" is another server ("staging"); connect with dbname=prod, or use the other server's login`. What still connects, to the login's own server as before: the login's own server by its id or its name, and any name that is no server at all (the application's own database name passed on by a proxy, `postgres`, no database). Before upgrading, check the clients and proxies that use an application login: if one names a database that is also the id or the name of another server here, change it to the login's own server, or rename that server. A connection without an application login is not changed: there the database name picks the server. The password is still checked first, so a wrong password says nothing about which servers exist.
