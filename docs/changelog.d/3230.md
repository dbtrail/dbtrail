- **PostgreSQL port: a `*` over a `char(n)` column that nothing reads stays on the copy** (#3230). Since #3107, a `*` inside a `WITH` or a subquery in `FROM` sent the statement to the source whenever a table it read held a `char(n)` column, so heavy reports that never used that column ran on the source. The port now follows the star through `WITH`s, subqueries and aliases and leaves the statement on the copy when no `char(n)` column can be read through it. A statement that names the column, returns it through another `*`, uses the row whole, compares or orders the rows of the block with the `*`, casts to `char(n)`, takes arguments, reads a table with a column of a domain or another non-built-in type, or has a shape the port does not follow still goes to the source. A `char(n)` column named in the last `SELECT` of a `WITH` also still goes there, because the port would announce it as `text` rather than `bpchar(n)`.
