- **Removing a PostgreSQL server in the web interface now warns that its replication slot stays on the source** (part of #3079). The question said "nothing happens to the server itself", while the server's replication slot stays on the source and PostgreSQL keeps WAL for it until it is dropped, which can fill the source's disk. For a PostgreSQL server the question now says so, shows how to check the slot first, and gives the `SELECT pg_drop_replication_slot('...')` statement to run connected to the slot's database; when no valid slot name is saved, it shows how to list the slots instead. DBTrail still does not drop the slot. The text for MySQL and MariaDB servers is unchanged.
