- **A PostgreSQL server's first snapshot update no longer warns of a gap that is not there** (#2843). The update of a snapshot warned "possible gap between baseline and this table's first indexed event" whenever the table's first captured change came after the snapshot, which on a new server is every table nobody wrote to in between. The proof that rules a gap out was the index holding an event at or before the snapshot, and a new index holds none. A PostgreSQL capture now records, once, where it started reading its source from (`stream_state.pg_capture_from_lsn`): the consistent point of the slot it created, or the position of a slot that was already there. A fold of a PostgreSQL snapshot reads it, and a capture that started at or before the snapshot's floor proves there is no gap. A capture that started after the snapshot still gets the warning, and `bintrail-pg reset` removes the record with the slot. An index written by an older capture has no record and keeps the warning until its next full snapshot. MySQL and MariaDB sources are not affected.
