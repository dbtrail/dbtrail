- **Time travel on the MySQL port prints a `FLOAT` and a `DOUBLE` cell as MySQL does** (#2851). `_snapshot` and `_flashback` printed a number in Go's text: a `DOUBLE` `1e21` came out `1000000000000000000000` or `1e+21`, and a `FLOAT` read from a snapshot was widened (`0.1` as `0.10000000149011612`). Both shapes, one row or the whole table, now print a `FLOAT` with six significant digits and a `DOUBLE` with the shortest exact text, in MySQL's fixed and exponent forms (`1e21`, `1e15`), and a column declared `FLOAT(M,D)`, `DOUBLE(M,D)` or `ZEROFILL` with its decimals and zero padding (`0.10` in a `DOUBLE(10,2)`), by the column's declaration in the schema snapshot in effect at the AS OF instant; measured against MySQL 8.0 on 5,500 values. A value recorded before an `ALTER TABLE ... MODIFY` between `FLOAT` and `DOUBLE` is printed as MySQL holds it after the change (a `FLOAT` `0.1` as the `DOUBLE` `0.10000000149011612`). A prepared statement gets the exact value. A column whose declaration the schema snapshot does not record (a snapshot taken before column types were recorded) prints as one declared without digits, with a warning (code 1105, read with `SHOW WARNINGS`) that names it.
