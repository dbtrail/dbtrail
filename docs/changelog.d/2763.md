- **A PostgreSQL server's scheduled snapshot update is tested end to end, and the README says it runs** (#2763). The README said a PostgreSQL source had a one-time copy with no scheduled update. It does run: a schedule's slot builds the next snapshot from the previous one and the captured changes, without reading the source again. A new integration test registers a PostgreSQL server, captures it, takes the full read, changes rows on the source, fires the schedule's slot and reads the new snapshot, with nothing between the slot and the Parquet file replaced by a test double; CI runs it against a real PostgreSQL and fails if it did not run. What the update does not do on PostgreSQL is look for tables created after the previous snapshot: those enter the copy with the next full snapshot, and `docs/postgres.md` now says so.
