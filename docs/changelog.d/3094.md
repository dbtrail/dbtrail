- **PostgreSQL fresh mode: writing a table's newest changes to disk takes about a fifth less time** (#3094, part of #3081). Each time the recent changes of a PostgreSQL table were written to a file, every row was built twice: once only to check that it could be written, then again to write it. A row is now built once, as it is written. The whole write of 400,000 changed rows went from 3.7 s to 2.9 s on the test box, with 40 % fewer allocations, and the files are the same byte for byte. A row that cannot be written still leaves no file behind and the table's changes still count as not written. MySQL and MariaDB sources are not touched: they always built each row once.
