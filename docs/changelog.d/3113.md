- **A PostgreSQL full read no longer writes outside the snapshot folder because of a table's name** (#3113). PostgreSQL allows a quoted name to hold a `/` or to be `..`, and the read joined the schema and table names into the file path as they were: such a table could land in another folder, including outside the snapshot, while the snapshot was published as complete. A schema named like one of the snapshot's own control files (`_SUCCESS`, `_MANIFEST`, `_INCOMPLETE`) made every full read of that server fail, and a table named like the temporary file of `views.sql` was silently missing from S3 and from downloads. These tables are now left out, the rest of the snapshot is published, and the run names each one with the reason, on the web console and in `bintrail-pg baseline`. If no table can be stored, the run stops before it creates a replication slot. Names that stay inside their folder are stored as before, including a table named `.` or `..` and names with a `\`, spaces or non-ASCII letters. Existing snapshots are read as before. A file an earlier version wrote outside the snapshot folder is not removed. MySQL and MariaDB sources are not affected.
