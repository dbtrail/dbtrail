- **The PostgreSQL port returns up to 200,000 rows for one statement** (#3308, #3286). Its row cap was the MySQL port's 10,000, so a report with a larger result was run on the copy and then refused with `54000`, where PostgreSQL alone answers it: CH-benCHmark's Q16 returns about 100,000 rows and failed on every run. The PostgreSQL port's default (`--sql-port-max-rows`) is now 200,000; the MySQL port keeps 10,000. What one statement holds in memory stays bounded by its bytes (64 MB) and the port's 256 MB for every result at once, as before. The rule that sends an expensive statement to the source when its plan estimates a result over the cap (`result_over_row_cap`) moves with it, so fewer such statements go to the source. `/status` now counts the results refused for their size per server, under `result_too_large`, as `rows` or `bytes`. `SQL_PORT_MAX_ROWS` in the compose `.env` (`BINTRAIL_CONSOLE_SQL_PORT_MAX_ROWS`) still sets the cap of both ports when given. MySQL and MariaDB are unchanged.
