- **PostgreSQL table deltas: a snapshot update reads a table file's keys once instead of twice, and says how long each step took** (#3179, part of #3082 and #3085). To find the changed rows in a table file, an update used to read the key columns of the whole file twice: once to make sure no key was empty (NULL), once to find the rows. The process now remembers, per file, that it has no empty key, so the next updates over the same file read its keys once. A file is told from another by its device, inode, size and time of last write, the way the rest of the snapshot code tells them apart. A file with an empty key is refused every time, and a file replaced under the same name is read again. The memory is bounded and starts empty after a restart. On a 10-million-row file this took the lookup from 2.0 s to 1.8 s. The lines a PostgreSQL delta writes to the log now also carry the milliseconds of each step (reading the index, folding, finding the rows, reading the previous delta, writing the new one, folding it into the file) and of the whole. MySQL and MariaDB sources are not touched.
