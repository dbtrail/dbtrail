- **The PostgreSQL port sends to the copy only what is expensive on the source** (#PR). With a forwarding user, every statement the copy answers as PostgreSQL does went to the copy, reads by a primary key included; the copy has no index, so `SELECT ... WHERE id = $1` on a table of 2 million rows took 15 seconds there, queued behind one worker, against about a millisecond on PostgreSQL. The port now asks the source for the statement's plan first (`EXPLAIN (FORMAT JSON)`, `GENERIC_PLAN` for a prepared statement with parameters) and sends it to the copy only when the plan's Total Cost is 50,000 or more, or a sequential scan in it is estimated at 1,000,000 rows or more; otherwise the source answers it (`cheap_plan` in `/status`). An `EXPLAIN` the source refuses sends the statement to the source, which answers with its own error (`explain_failed`). The thresholds are `--route-cost-threshold` and `--route-scan-rows` of `pg-router` (`BINTRAIL_PG_ROUTER_COST_THRESHOLD`, `BINTRAIL_PG_ROUTER_SCAN_ROWS`; `PG_ROUTER_COST_THRESHOLD` and `PG_ROUTER_SCAN_ROWS` in the compose `.env`). On PostgreSQL 15, which has no `GENERIC_PLAN`, a prepared statement with parameters goes to the source.
