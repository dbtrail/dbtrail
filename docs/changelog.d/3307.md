- **The PostgreSQL port tries a connected join order before sending a statement to the source for its joins** (#3307). When the copy's join check finds a dangerous join both in the engine's own order and in the order written, a `SELECT` whose `FROM` is a plain list of tables (`FROM a, b, c`) and whose `WHERE` is an `AND` of conditions is written again, through the engine's own parser, with the largest table first and each next table one that already has a condition with those before it. It runs in that order when the same check finds no dangerous join there; otherwise it is refused and goes to the source as before. The new text must parse back to the same statement and give the same columns, and it never reaches the client, the audit record or the logs, which say only the order used. The CH-benCHmark's Q21, which ran out of memory in one order and was a 6e11-row cross product in the other, answered in 6.8 to 8 s on a frozen copy, against 30 s to 5.5 min on the source. `/status` counts it as `connected_order` under `join_checks`. The MySQL port is unchanged.
