- **On the PostgreSQL port, a statement the source answers no longer waits for a worker of the copy** (#3213). The port read the copy's list of columns before it asked the source for the statement's plan, and that list is read by the same workers that run reports: with all of them busy, a read by key could wait up to 30 seconds, once per connection every 10 seconds and on every new connection. The plan now comes first, as on the MySQL port, and the list is read only for a statement headed for the copy. With one worker held by a long report, a read by key went from 30 s to a median of 1.4 ms (worst 9 ms).
