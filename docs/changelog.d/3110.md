- **PostgreSQL: the web interface, recover, query key ranges, the MCP tools and the Iceberg export see every table's shape** (#3110). A PostgreSQL index saves one table shape per schema snapshot, so reading "the newest snapshot" the MySQL way found only the table saved last. In the web interface the other tables were missing from the table list and answered "table not found in snapshot"; `recover` checked an undo against the wrong shape and could write a column the table no longer has (`INSERT ... legacy ...`), which would fail when applied; `--pk-min`/`--pk-max`, the MCP `pk_min`/`pk_max` and `reconstruct` tools and `bintrail export iceberg` answered "not found" for every table but one. On a PostgreSQL index these now load each table's own newest shape, the loader `verify` and full-table `reconstruct` already used: the undo with a dropped column is refused with the usual drift message, and a key range gets the PostgreSQL refusal that names why. The web interface also reads the shapes again when the index saves a new one, so a column dropped or a table first changed after it opened is seen without a restart; this costs a PostgreSQL server one short query per request, and a reload that fails keeps the shapes it had and is not tried again for the same snapshot within 30 seconds. The choice is read from the index (`stream_state.flavor = 'postgres'`); MySQL and MariaDB indexes, and indexes whose flavor cannot be read, load exactly what they loaded before, once, as before.
