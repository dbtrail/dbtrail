- **A PostgreSQL capture publishes Prometheus metrics** (#2762). It published none: `bintrail-pg stream` had no `--metrics-addr`, and under `bintrail-console watch` the daemon's `/metrics` had nothing for a PostgreSQL server. It now publishes the stream metrics a MySQL capture does, under the same names (`bintrail_stream_events_indexed_total`, `bintrail_stream_last_flush_timestamp_seconds`, the lag gauges and the rest), so one dashboard and one alert rule serve both, plus four of its own: `bintrail_pg_last_commit_lsn`, `bintrail_pg_slot_retained_wal_bytes`, `bintrail_pg_slot_health_timestamp_seconds` and `bintrail_pg_caught_up_timestamp_seconds`. `bintrail-pg stream` takes `--metrics-addr` (env `BINTRAIL_METRICS_ADDR`), and refuses to start when it cannot open that address; under `watch` the PostgreSQL servers appear on the address the daemon already serves, labelled by server like the MySQL ones. The `bintrail_index_*` gauges are not published for a PostgreSQL capture. Nothing changes for a MySQL capture. See `docs/observability.md`.
