- **A snapshot of a `latin1` table no longer comes out unreadable now and then** (#2899). mydumper 1.0.3 with its stock `/etc/mydumper.cnf` heads every dump file with `SET NAMES utf8mb4` on MySQL 8 and MariaDB 11 and 12, but a thread that dumps rows before any schema job writes the bytes as stored, so the same table came out converted to UTF-8 or as stored `latin1` bytes from run to run (1 dump in 15 with 4 threads, every dump with 8, measured on MariaDB 12.3). The full read trusted the header, kept the stored bytes, and DuckDB refused the table's file: the copy, `reconstruct` and `verify` stopped with `Invalid string encoding ... is not valid UTF8`. Each dump file is now read by its rows: a `latin1` value that is not UTF-8, or that holds a character `latin1` does not have, marks the file as stored bytes and it is converted. The snapshot's content digest is taken over the stored bytes either way, as `verify` reads the live table. A text value in another character set that is still not UTF-8 now gets a warning naming the table and the column when the snapshot is written.
