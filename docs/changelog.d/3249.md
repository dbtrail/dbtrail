- **PostgreSQL port: a statement that uses a column the copy does not compare as PostgreSQL does is no longer answered by the copy** (#3249, refs #3233). PostgreSQL compares a domain over `char(n)`, `inet`, `jsonb`, `money`, a range, `bytea` or `oid` by value, and the copy compared what is written, so `WHERE dc = 'a'` found no rows where PostgreSQL finds nine, with no notice. A statement that compares, groups, joins, sorts, aggregates, applies `DISTINCT` to or passes to a function such a column (a type that is not built in, a built-in type the copy holds as text, `bytea` or `oid`) now goes to the source, or is refused on a server without a forwarding user. So does an argument declared `bpchar`. **The cost:** those reports run on the source at its speed, even when the copy would have answered them right. Only showing such a column stays on the copy, and a statement that does not read it is not affected.
