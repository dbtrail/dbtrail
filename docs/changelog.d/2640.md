- **A snapshot update can take one table from a read of that table alone** (#2640, second of five parts). Internal for now: nothing uses it yet, so a refused table still waits for a full read of its server, as `docs/full-reads.md` says. The update takes, per table, a file read again from the source and kept outside the snapshots folder, folds the table from that file and every other table from its snapshot, all to the same binlog position, and publishes one ordinary snapshot. It refuses, without falling back to the old snapshot of the table, a read that is unfinished, that is not that table's, that sits inside the snapshots folder, or that was taken at a position capture has not reached yet.
- **The read of some tables alone, for such an update** (#2640, third part, first half). Internal for now: nothing calls it, so the daemon behaves as before. It reads the given tables from the source into a working folder, as finished files a snapshot update can take, or returns an error and no file at all. It declines, so that the caller takes a full read, under the `no-lock` and `safe-no-lock` lock modes, for a name with a comma or a dot, and for a schema mydumper cannot look up in a table list.
