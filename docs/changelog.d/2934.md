- **PostgreSQL: SQL on the copy reads a table's delta with its file** (part of #2757). With `BINTRAIL_PG_TABLE_DELTAS=1` (off by default), a snapshot update publishes a changed table as its previous file and two small files of changes beside it, and SQL on the copy read the file alone: the table as it was at an earlier update. The SQL page, the ports and the AI connection now read the file as its delta leaves it, with the table's tail over that. A views file that follows later snapshots, or names its files in S3, still reads the file alone, so the switch stays off. Also fixed in the delta's own reads: a table whose name holds a glob character (`or*ders`) was read with the file of `orders` beside it.
