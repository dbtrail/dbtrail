- **A PostgreSQL snapshot update sees a column change that no write followed** (#3112). PostgreSQL's change stream describes a table only when it next carries a change of it, so after `ALTER TABLE ... DROP COLUMN`, `ADD COLUMN`, `RENAME COLUMN` or `ALTER COLUMN ... TYPE` on a table nothing wrote to afterwards, each scheduled update kept publishing the table with its old columns: a dropped column was still answered, an added one was missing, and a column dropped and added again under the same name kept the values the source no longer has. The update now asks the source's catalog for every table's columns in the read it already makes for new tables, and a table whose columns are not the ones its snapshot file records stops the update as a captured column change does: nothing is published, the run names the table and what changed, and the schedule takes a full read in its place where it may. An index, a default or `NOT NULL` stops nothing. A change made between that read and the publication is seen by the next update, and a source that cannot be reached is said on the run, with the update published from what was captured, as before.
