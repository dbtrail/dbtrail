- **A PostgreSQL full read sends only its own snapshot to S3** (#2761). On a PostgreSQL server with an S3 destination, every full read handed the uploader the server's whole snapshots folder, so each one sent again every snapshot on the local disk, including ones the S3 cleanup had removed by age and updates that **Send to S3 every** was keeping on the local disk. Now it sends the snapshot it just wrote, to that snapshot's own folder in the bucket, the way a MySQL full read does. As for MySQL, the snapshot counts as made once it is complete on the local disk, so a scheduled update can run while the upload is still going; a failed upload is reported with the folder the snapshot is in and the place it did not reach; and after its own upload the full read sends any older complete snapshot the bucket does not have, skipping files already there, snapshots held by the upload interval and snapshots past the age set for S3. A PostgreSQL full read also records the index's high-water mark before it starts (`index_mark` in the run), so the update after it is measured by the schedule's cost model. Nothing changes for MySQL or MariaDB servers, and nothing is removed from the disk or the bucket.
