- **The docs say what an application sees when the router stops, and how to fall back to MySQL** (#2676). With Engine Routing on, an application connects to DBTrail's MySQL port, so it depends on the router: the README's Limits and `docs/analytics.md` said nothing failed over and the application never pointed at DBTrail, and now say that. `docs/time-travel-sql.md` has a new section, When the router stops, measured in one run (DBTrail 0.137.0, MySQL 8.0.46, ProxySQL 3.1.12): a stopped router refuses connections at once (`2003`) and cuts the statement in flight (`2013`), a killed one is back in under a second with the Docker stack, a frozen one leaves clients waiting for their own timeout, an open transaction is rolled back, and MySQL is untouched. It then gives a ProxySQL configuration that sends `SELECT`s to MySQL while the router does not answer, with the health check it needs (a ping every 2 seconds; ProxySQL's default is too slow for a frozen router), what it covers and what it does not. Docs only.
