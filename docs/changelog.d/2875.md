- **A PostgreSQL snapshot update refuses a transaction whose changes of one key do not describe one row** (#2875). A `DEFERRABLE` primary key lets two rows hold the same key value until the statement or the transaction ends. A transaction that inserted a new row 1 and then deleted the old row 1 was captured as an INSERT and a DELETE of key 1, the update kept the last one, and the copy lost the new row with no error. The update now checks, for the changes one transaction makes to one key, that each starts from the row the one before it left, and refuses the table when it does not, naming the key and the transaction's commit LSN. A row inserted and deleted again, inserted and updated, updated twice, or deleted and replaced in one transaction is applied as before, and so is a transaction capture delivered twice after a restart. Not seen: a row inserted as an exact copy of another, every column equal, followed by a delete of the original. MySQL and MariaDB are not changed.
