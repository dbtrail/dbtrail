- **The PostgreSQL port serves TLS and logs in with SCRAM-SHA-256** (#2766). `bintrail-console pg-router` takes `--tls-cert` and `--tls-key` (`BINTRAIL_PG_ROUTER_TLS_CERT`, `BINTRAIL_PG_ROUTER_TLS_KEY`), loaded the way the MySQL port loads its own, so the same files serve both ports and a client connects with `sslmode=verify-ca` or `verify-full`; with no certificate set a client that asks for TLS gets one made up at start (`sslmode=require` works, verifying refuses it). The login is SCRAM-SHA-256 with TLS and without, so the password no longer crosses the network in clear text, and over TLS the port offers SCRAM-SHA-256-PLUS for `channel_binding=require`. TLS is offered and never required, as on the MySQL port: `sslmode=disable` still connects, without the password on the wire. Because of that, `--listen` now takes any address instead of this machine's only, and an address other machines reach is named at start. An expired certificate is served with a warning at start; a missing, unreadable or mismatched file stops the process before it listens, with the reason. A client needs SCRAM support (libpq 10, JDBC 42.2 or later). `bintrail-pg flashback` gets the same login and TLS (`--tls-cert`, `--tls-key`, `BINTRAIL_PG_FLASHBACK_TLS_CERT`, `_KEY`). Checked with `psql`, `pgx`, psycopg 3 and JDBC in every `sslmode`. See [SQL on the copy from `psql`](postgres.md#sql-on-the-copy-from-psql).
