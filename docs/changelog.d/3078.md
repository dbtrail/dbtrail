- **PostgreSQL: a snapshot is no longer read while the replication slot is still being created** (#3078). On a busy source PostgreSQL can take a while to finish creating capture's slot (it waits for the transactions that were open to end). A first snapshot taken in that time was anchored on a slot that had no position yet: the changes committed until the slot got one were in neither the snapshot nor the captured changes, the command ended without an error, and every later update carried the wrong rows (416 of 2,221 sampled rows in the run where it was seen). A snapshot now waits for the slot to have its position, up to 5 minutes, and is refused with nothing read past that; a slot that already has one is read at once, as before. When the tables are read the slot is checked again: a snapshot whose slot was removed, or that starts before the position capture started reading from, fails and is not kept. A snapshot already taken that way is not updated: the update refuses the tables whose snapshot starts before capture did, and the schedule reads the source again in its place. Tables an update has rewritten since can no longer be told apart; on an install where the first snapshot was taken while capture was not attached yet, take one more snapshot by hand (`snapshot run`).
