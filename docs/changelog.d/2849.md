- **The MySQL port declares a date and time as MySQL does** (#2849, #2801). The copy declared every date and time it answered as a `DATETIME` with six fractional digits, and printed a value with only the digits it needed, where MySQL declares the column's own (none for a `DATETIME` and for `FROM_UNIXTIME` of a whole number, three for a `DATETIME(3)`), types a `TIMESTAMP` column as a `TIMESTAMP`, and prints every value with exactly those digits (`12:00:00.120`, `12:00:00.000000` in a `TIMESTAMP(6)`). A client that formats by the declared digits could show `.000000`, and a prepared statement sent six. The port now reads the digits and the type from the table's definition for a column, `MIN` or `MAX` of one, a star, `COALESCE`, `CASE`, `IF`, `GREATEST`, `LEAST` and a date step by a whole `INTERVAL` over such columns, and knows `NOW()`, `UTC_TIMESTAMP()` and, under routing, `FROM_UNIXTIME` of a whole number. Under routing, a date and time it cannot tell (a `CAST`, a `TIMESTAMP '...'` literal, a column of a derived table) is now answered by MySQL, and so is a `DATE` stepped by a day, which MySQL returns as a `DATE`; the port without routing answers those as before. On MariaDB 11.8 and 12.3, `FROM_UNIXTIME` stays declared `DATETIME` where the source declares `TIMESTAMP` (#2858).
