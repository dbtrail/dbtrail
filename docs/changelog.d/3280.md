- **PostgreSQL snapshot updates find a large table's changed rows much faster** (#3280, #3085). A snapshot update used to read the key columns of a table's whole file to find the rows that changed, which on tables of tens of millions of rows could take longer than the update had. A PostgreSQL table file now gets a small key index beside it (`<table>.pg.keyidx`), written with the snapshot and kept with the file when it is carried into the next snapshot. On a 10-million-row table, finding 1,000 changed rows went from 1.8 s to 0.3 s. Every row the index finds is checked against the file before it is used, and a missing, damaged or outdated index means the file is read as before. Files written by earlier versions get an index the next time their table is written in full. `BINTRAIL_KEY_INDEX=0` turns it off, as it does for MySQL. MySQL and MariaDB sources are not affected.
