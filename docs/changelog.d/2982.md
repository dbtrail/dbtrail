- **A PostgreSQL table that is not at `REPLICA IDENTITY FULL` no longer stops capture of every table**. Before, a table added to the publication at the default replica identity made capture stop with "relation ... is not at REPLICA IDENTITY FULL", and it could not be restarted even after the `ALTER TABLE`: PostgreSQL re-sends the old changes as they were written, so the same error came back on every start, and only dropping the slot (a full re-read) recovered. Now that table's changes are skipped and never indexed with a partial before-image, the other tables keep flowing, the log names the table with the exact `ALTER TABLE ... REPLICA IDENTITY FULL` to run, and `status` reports capture as degraded under the new reason `replica_identity_not_full`, with the table named. PostgreSQL capture now keeps the same skip ledger as MySQL capture (`stream_state.capture_skips`), carried across restarts. After the `ALTER TABLE`, capture of the table resumes by itself. Startup no longer refuses a table below FULL either; it warns and skips it. `bintrail-pg doctor` and the console's check when adding a server still fail on such a table.
