- **`bintrail-console pg-router`: a PostgreSQL-protocol port that runs read-only SQL on the copy** (#2765). A process of its own, beside `watch` and apart from the MySQL port (`router`), which this change does not touch: its own listener, workers and memory, set where it is started (`--workers`, `--threads`, `--sql-memory`, `--max-connections`, small by default). `psql "host=127.0.0.1 port=5433 dbname=<server id or name>"` connects with the password created for SQL clients in the web interface, the access token or a server's application login, and each statement is answered by that server's copy, by PostgreSQL's rules. It serves PostgreSQL servers only; a MySQL or MariaDB server is refused by name. Nothing is sent to the source and a statement that is not a read is refused. This first version sends every column as text, takes the simple query protocol only, serves no time travel, and listens on this machine alone because the password is asked for in clear text and there is no TLS yet. `SET search_path`, `SET ROLE` and a `SET TimeZone` other than UTC are refused, since the port would not act on them. See [SQL on the copy from `psql`](postgres.md#sql-on-the-copy-from-psql). Three changes reach `bintrail-pg flashback` too, which shares the wire: a message of nothing but semicolons is an empty query, as on PostgreSQL, where it was an error; a client message may announce at most 64 KiB before the login and 16 MiB after it, where there was no limit and a client with no password could make the process set aside the memory it announced; and a client refused because `--max-connections` is reached is told so in an error (53300), where its connection was closed without a word.
