- **The PostgreSQL port decides per statement whether the copy or the source answers** (#2770). With a server's forwarding user, `bintrail-console pg-router` lets the copy answer a statement only when everything in it is something the comparison harness (`internal/pgcompare`) measured answering as PostgreSQL does, and sends the rest to the server's own PostgreSQL, read-only: a function, operator, cast or construct the copy answers differently or not at all (`avg` and division of a `numeric`, `round` of a float, a division that can meet zero, `~`, `SIMILAR TO`, `->` and `->>`, a number with an exponent, `::text`, `upper`/`lower`/`ILIKE`, `COLLATE`, `AT TIME ZONE`, `FOR UPDATE`, every function not on the list), the clock and the session (`now()`, `CURRENT_DATE`, `current_user`), text sorted or compared by order (the source orders it by its collation), and a session `TimeZone` other than UTC. A statement the copy then cannot run (a table it does not hold, a reserved word of its dialect, a value it does not read, a busy or lagging copy; a result over the port's caps is still refused) or answers with a `numeric` declared without precision goes to the source before the client is told anything, in the simple and the extended protocol; a prepared statement keeps its side. Without a forwarding user nothing changes. A server that hides tables or columns sends nothing to its source, a transaction block's statements included, since a statement run there reads past the rules: before this, a client's `BEGIN` on such a server read the hidden tables on the source (#2771). New `--status-addr` serves `/status`: per server, how many statements each side answered and why (the MySQL port's reason names where they mean the same), and with `--status-statements` a row per statement shape, values blanked. Checked against PostgreSQL 16 with psql, pgx (every query mode), psycopg 3 and JDBC.
