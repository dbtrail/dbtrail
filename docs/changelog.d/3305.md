- **The PostgreSQL router says when its statements, its tails and the index MySQL may need more memory than the machine has** (#3305, #3296). Each of the three is sized on its own, and on an 8 GB host running 2 workers at 2 GB, the tails and a 3 GB index buffer pool, the machine swapped for hours and the kernel's OOM killer stopped DuckDB workers and then the index MySQL, with no warning before. The router now adds their ceilings up when it starts and once a minute after: the statements that can run on the copy at once (`--workers` plus the one kept for short statements), each at its SQL memory plus the headroom DuckDB takes outside that limit; what the tails may hold; the 256 MiB of results held for clients; and the buffer pool of each index MySQL of a PostgreSQL server that runs on the same machine (an index elsewhere, or one that does not answer, is not counted, and the line says so). With no ceiling of its own the sum is compared with the machine's memory; with `PG_ROUTER_MEMORY` or `PG_ROUTER_MEMORY_SHARE` below 1, with that ceiling and without the buffer pool. Past it the start-up lines carry a `WARNING`, the log a `WARN` each time it goes over, both with what fits: fewer `PG_ROUTER_WORKERS` at the same SQL memory, or one worker and the SQL memory that fits it. `/status` shows it as `memory`. Nothing is changed and the router never refuses to start; with no PostgreSQL server listed nothing is said. The factory settings (4 workers at 2 GB) are over on a 16 GB machine with the index MySQL's default buffer pool, so the router warns there; 2 workers fit. MySQL and MariaDB are unchanged.
