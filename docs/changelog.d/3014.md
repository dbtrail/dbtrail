- **A first PostgreSQL install, as the docs and the installer tell it** (#3014). `docs/postgres.md` said DBTrail's role needs no `SELECT`; capture does not, but the first copy reads every published table as that role and failed with `permission denied` after every check of `server add` had passed. The setup now grants it (and says what covers tables created later, and `USAGE` for a schema other than `public`), and its examples use the `public` schema instead of a schema named like the database. `server add --help`, `port --help`, the PostgreSQL port's panel and the docs now say the same thing about who answers there: the copy alone until the server has a forwarding user (`server forward-user`), and with one, what the copy is not known to answer as PostgreSQL does, and transaction blocks, on the PostgreSQL, read-only. The installer's closing text adds the SQL for the dbtrail user before `server add`, a PostgreSQL server with `--flavor postgres`, the link that makes a bare `dbtrail` work, and the SSH tunnel for a remote machine.
