- **`server add --flavor postgres` checks that the role can read the published tables** (#3022). Recording changes needs no `SELECT` and the first copy of the tables does, so a role without it passed every check and its first snapshot then failed with `permission denied for table ...` (`42501`). A new check, **Read access to the published tables**, asks PostgreSQL whether the role has `USAGE` on each table's schema and `SELECT` on the table, or on every column the copy reads; ownership, a superuser, a role inherited from another and `pg_read_all_data` count as they do for the copy itself. A role that cannot read a table is refused, in the terminal and in the web interface, with the `GRANT` to run, each name quoted. DBTrail grants nothing by itself. Up to ten tables each get their own statement; past that the check names the first ten, counts the rest, and prints `GRANT SELECT ON ALL TABLES IN SCHEMA` once per schema. `bintrail-pg doctor` runs the same check. A snapshot asks again before it starts and is refused with the same statement before the replication slot or any file is created, which covers a server added by an earlier version, a table that joined the publication since, and a permission taken away.
