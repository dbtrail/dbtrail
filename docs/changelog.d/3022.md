- **`server add --flavor postgres` says when the role cannot read the published tables, and a snapshot is refused before it starts** (#3022). Recording changes needs no `SELECT` and the first copy of the tables does, so a role without it passed every check and its first snapshot then failed with `permission denied for table ...` (`42501`), after the replication slot had been created. A new check, **Read access to the published tables**, asks PostgreSQL whether the role has `USAGE` on each table's schema and `SELECT` on the table, or on every column the copy reads; ownership, a superuser, a role inherited from another and `pg_read_all_data` count as they do for the copy itself. It is a warning, in the terminal, in the web interface and in `bintrail-pg doctor` (which still exits 0): the server is added, started and its changes recorded, because none of that needs the permission. It shows the `GRANT` to run, each name quoted, and DBTrail grants nothing by itself. Up to ten tables each get their own statement; past that the check names the first ten, counts the rest, and prints `GRANT SELECT ON ALL TABLES IN SCHEMA` once per schema. The snapshot is what is refused: it asks the same question before it starts and stops with the same statements before the replication slot or any file is created, which also covers a server added by an earlier version, a table that joined the publication since, and a permission taken away.
