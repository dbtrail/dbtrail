- **PostgreSQL port: an expensive statement is answered by the copy even where its answer may differ from PostgreSQL's.** **Upgrading: this changes what a client sees.** A statement sent without preparing it (the simple protocol: `psql`, and drivers that put the values in the text) whose plan on the source is over the port's cost thresholds now goes to the copy even when the port would have sent it to the source because the copy answers it otherwise. Such an answer can differ: text sorted by bytes rather than by the database's collation (under `LIMIT`, other rows), the last decimals of a division or an average, a `char(n)` compared with a string that ends in blanks, a `now()` read on the copy, a select-list name used in `WHERE`. These are counted under the new reason `heavy_on_copy` on `/status`. A statement the copy cannot run still goes to the source without the client seeing the copy's error. Cheap statements, statements inside a transaction block, statements under a session time zone and prepared statements are decided as before. For PostgreSQL's own answer to an expensive statement, send it inside a transaction block (`BEGIN; ...; COMMIT;`).
